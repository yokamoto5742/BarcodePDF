# 変更履歴

このプロジェクトのすべての重要な変更は、このファイルに記録されます。

フォーマットは [Keep a Changelog](https://keepachangelog.com/ja/1.1.0/) に基づいており、
バージョン番号は [Semantic Versioning](https://semver.org/lang/ja/) に従っています。

## [Unreleased]

### 変更
- 取込フォルダ（`target_dir`）から直接バーコードを読み取り、完了フォルダ／エラーフォルダへ振り分ける1段構成にした。監視スレッドが1本、ファイル移動が1回になり、処理の経路が一本化された
- ステータス表示をキュー経由に変更。監視スレッドはキューへ積むだけとし、tkinterのウィジェット更新はメインループ側（`after`）でのみ行うようにした

### 削除
- 中間フォルダ `processing_dir` と、その設定項目・GUIの「処理フォルダ」行を廃止
- watchdogによるフォルダ監視（`PDFHandler`）と、起動時の残ファイル処理 `process_existing_pdfs` を廃止（ポーリングが両方を兼ねるため）。依存関係から `watchdog` を削除

## [1.1.1] 2026-09-04

### 追加
- 取込フォルダ（`target_dir`）の監視をGUIアプリに統合。スキャナーが出力したPDFを処理フォルダへ自動的に移動してからバーコードを読み取る流れにした
- GUIの設定画面に取込フォルダの行を追加

### 変更
- 取込フォルダの検出をファイルイベントからポーリング＋安定性チェック（サイズと更新日時が前回走査から不変）に変更。スキャン直後にファイル名を変更するスキャナーでも取りこぼさず、書き込み途中のファイルも読まない
- `service/file_move.py` の単独常駐スクリプト機能を廃止し、`TargetDirWatcher` クラスとしてアプリのスレッドで動作させるようにした（起動するプロセスは `main.py` のみ）

## [1.1.0] - 2026-09-02

### 追加
- PDFバーコード読み取りロジックを改善：PDF上部帯のみを高解像度でレンダリングしてCODE128バーコード検出精度を向上
- バーコードデータをファイル名として安全に使用できるか検証する`is_valid_barcode`関数を追加
- service、utils、appモジュール向けの包括的なユニットテストを追加（100%カバレッジ対応）
- ビルド時にpyzbarをバイナリとして収集するオプションを追加

### 変更
- バーコード読み取り処理を最適化：複数バーコード検出時は最も幅の広いものを採用
- CODE128シンボルタイプのみを対象に限定（QRコード等は対象外）

### 修正
- 空のPDFやページがないPDFの処理を改善（Noneを返却）

- 初版リリース
